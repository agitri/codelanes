# AI Flows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An AI (through PhpStorm's MCP server) hands CodeLanes the hops of a request flow. CodeLanes checks them
against the code, draws them as proven (solid) or claimed (dotted) lines, follows the ordinary calls itself and saves
the flow as a `*.flow.json` dot file.

**Architecture:**
- `dev.codelanes.flow`, all without UI:
  - `Flow` (model).
  - `FlowFiles` (one JSON file per flow, plus the known folders).
  - `FlowResolver` (PSI → block ids, proven flags, unknown and gone references).
- `BlocksSession.showFlow` puts a resolved flow on the canvas, much like `followChain`.
- `FlowService` ties it together: resolve, open the canvas, save, reply text.
- `dev.codelanes.mcp.FlowTools` is a thin MCP toolset over `FlowService`, loaded only when `com.intellij.mcpServer`
  is present.

**Tech Stack:**
- Kotlin 2.4.21, kotlinx.serialization (compiler plugin; the runtime comes with the IDE).
- IntelliJ Platform Gradle Plugin 2.19.0, PhpStorm 2026.1 with bundled `com.jetbrains.php` and
  `com.intellij.mcpServer`.
- JUnit4 / BasePlatformTestCase, Gson.

**Spec:** `docs/superpowers/specs/2026-10-12-ai-flows-design.md`

## Global Constraints

- Every gradle command needs `JAVA_HOME=/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home`.
- sinceBuild 251: PhpStorm 2025.1 has no MCP server. Everything MCP lives in classes only referenced from
  `codelanes-mcp.xml` (optional dependency). `verifyPlugin` must pass on 2025.1 and 2026.1.
- Hop kinds, exactly: `routes`, `middleware`, `dispatches`, `listens`, `binds`, `calls`.
- The AI never writes or explains code. Nothing is drawn that doesn't resolve in the code.
- Block ids follow the builder:
  - `method:<name>` for methods of the open class.
  - `callee:<\Fqn>::<name>` for others; the FQN has a leading backslash and is the *declaring* class.
- Commits use the noreply email and end with the Co-Authored-By and Claude-Session lines.

## Review Focus

1. A reference to an inherited method (`Child::save`, declared in `Parent`) must give one block, not two
   (normalise to the declaring class).
2. An entry method whose class isn't the only class in its file: the canvas can't show it. The reply must say so,
   not throw.
3. A flow file that is broken or has an unknown `version` must never be overwritten or misread.
4. The MCP call arrives off the EDT. The folder picker and the canvas must run on the EDT, and resolving in a read
   action.
5. Hops that point at the open class's own `__construct` (no block of its own) must map to the class block.

  - `fun write(folder: VirtualFile, flow): String?` returns the path written, or null if refused.
  - `fun overwrite(saved: SavedFlow, flow): Boolean`
  - `fun folders(): List<String>`
  - `fun remember(folderPath)`
- `FlowFolders`: per-user workspace state (like `PinStore`) holding the folder paths.

### Task 3: FlowResolver

**Files:** `flow/FlowResolver.kt`, `test/.../flow/FlowResolverTest.kt`.

**Interfaces:**
- `FlowResolver.resolve(project, flow): ResolvedFlow` (in a read action).
- `ResolvedFlow` fields:
  - `entryFile: VirtualFile?`
  - `entryId: String?`: the block id on the entry file's canvas.
  - `entryProblem: String?`
  - `hops: List<ResolvedHop(fromId, toId, kind, proven)>`
  - `added: Set<String>`: the `\Fqn::method` keys for the builder's `added`.
  - `unknown: List<String>`: the AI's references that don't resolve.
- Block ids are computed relative to the entry file's class (`method:` for it, `callee:` otherwise; its constructor
  maps to `class:<\Fqn>`).

- [ ] Failing tests, with fixtures `OrderController`, `OrderService`, `OrderPlaced`, `SendOrderMail`,
  `OrderRepository` / `EloquentOrderRepository` and `Authenticate`:
  - `calls` proven when the call exists, claimed when it doesn't.
  - `dispatches` proven by `new OrderPlaced` in the from method.
  - `listens` proven by the first parameter type.
  - `binds` proven by implements.
  - `routes` and `middleware` claimed.
  - Unknown class and unknown method go in `unknown`, and their hops are dropped.
  - An inherited method normalises to the declaring class.
  - An entry in a file with two classes gives `entryProblem`.
  - References with or without a leading backslash both work.
- [ ] Implement, suite green, commit.

### Task 4: Showing a flow on the canvas

**Files:** `canvas/BlocksSession.kt`, `php/PhpBlockBuilder.kt` (only if `added` needs it), `BlocksSessionTest`.

**Interfaces:**
- `BlocksSession.showFlow(flow: ResolvedFlow, title: String, gone: List<String>)`
  - Replaces the previous follow or flow.
  - `added = flow.added`. Followed = entry plus hop targets, expanded `FollowRequestAction.DEPTH` levels like
    `followChain`.
  - Flow links (only those whose ends exist) are appended to every rebuilt model.
  - The entry block `flow:entry` (MORE kind, title = label) has a `routes` FLOW link to the entry id.
  - Gone references go into a MORE block `flow:gone`, "no longer in the code: …".

- [ ] Failing tests:
  - After `showFlow`, the model has FLOW links with labels, and the `flow:entry` block links to the entry method.
  - A claimed hop is `claimed`.
  - The flow survives a rebuild (typing).
  - A later `followChain` replaces the flow.
  - `gone` gives the grey block.
- [ ] Implement, suite green, commit.

### Task 5: FlowService and MCP tools

**Files:** `flow/FlowService.kt`, `mcp/FlowTools.kt`, `META-INF/codelanes-mcp.xml`, `plugin.xml`,
`test/.../flow/FlowServiceTest.kt`, `test/.../mcp/FlowToolsTest.kt`.

**Interfaces:**
- `FlowService(project)`:
  - `var chooseFolder: (suggested: VirtualFile?) -> VirtualFile?`, replaceable in tests.
  - `fun show(flow: Flow): String` returns the reply text. It is called on the EDT.
  - `fun open(saved: SavedFlow)`, for Follow a Request.
- `FlowTools : McpToolset`, with suspend functions:
  - `codelanes_show_flow(name, entry_label, entry_method, hops: List<HopInput>)`
  - `codelanes_list_flows()`
  - Both use `currentCoroutineContext().project` and `withContext(Dispatchers.EDT)`.
- `FlowTools.validate(...)` is pure and returns an error text or a `Flow`.

- [ ] Failing tests:
  - Reply text for success (`Shown "…": N hops, P proven, C claimed. Saved to …`).
  - Unknown references listed in the reply.
  - A bad kind is rejected with the list of allowed kinds.
  - A missing entry means nothing is shown, and the reply says why.
  - Cancel (`chooseFolder` returns null) means `not saved`.
  - The same name a second time overwrites without asking (`chooseFolder` not called).
- [ ] Implement:
  - `plugin.xml`: `<depends optional="true" config-file="codelanes-mcp.xml">com.intellij.mcpServer</depends>`.
  - `codelanes-mcp.xml` registers `<mcpServer.mcpToolset implementation="dev.codelanes.mcp.FlowTools"/>`.
- [ ] Suite green, `verifyPlugin` green, commit.
